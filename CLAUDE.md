# repostyle

A stdlib-only AST/token/line linter for repo-style conventions that ruff cannot express, published to PyPI as `repostyle` and run as a pre-commit remote hook or an installed package. It grew out of one service's in-tree style script, and the `RSnnn` rules here are now the canonical source every consuming repo reads. Most rules are Python-specific (AST-based); the comment-convention rules RS009 (paragraph wrapping), RS022 (tag format), RS030 (terminal punctuation), RS045 (temporal / diff-narrative markers), RS049 (acronym casing in prose), RS050 (disfavored Google Cloud product name), RS053 (bullet-list casing), RS054 (sentence-dash standard), and RS055 (banner comments) also run over TOML, YAML, and shell comments through a shared `#`-comment extractor, so a `#` comment is held to the same conventions whatever the language.

## Project context

Consuming repos add the hook to their `.pre-commit-config.yaml` pinned to a `repostyle-vX.Y.Z` tag, select the rule subset they want through a `[tool.repostyle]` table in their `pyproject.toml`, and inherit the base ruff settings from `ruff-base.toml`. RS006 (port purity) presumes a hexagonal `application/ports/` layer and RS003 (mock ban) presumes a `tests/fakes/` directory; a repo without those conventions should not select them. RS002 (test naming) and RS006 default to the `tests/unit/` and `application/ports/` layouts but re-scope through `test-naming-globs` and `port-path-globs`, so a repo keeping either elsewhere can still select them. The rest are general.

The `RSnnn` rules are the *subject matter* this package enforces on other repos. Their definitions, scope, and rationale live in the rule docstrings in the themed modules under `src/repostyle/rules/`; read the relevant module before changing rule behavior.

## Repository layout

- `src/repostyle/rules/` — the rules package. Each themed module holds the `check_*` functions for its rules; a rule's full definition and rationale live in its check-function docstring, so read that before changing behavior — the list below maps where each rule lives, it is not a spec. Themed rule modules:

  - `naming` — RS001 (acronym casing), RS010 (banned abbreviations), RS011 (vague class suffix), RS024 / RS026 (boolean naming; warn), RS025 (no `make_` in production), RS028 (`except` alias), RS044 (a `-> bool` function reads as a yes/no question; warn), RS051 (a string parameter named for a Google Cloud resource collection wants the `_id` suffix; warn); it also holds the acronym set and the RS049 prose scanner, plus the RS050 disfavored-Google-Cloud-term map and scanner, that the docstring and comment halves of those rules consume
  - `docstrings` — RS004 (no `Attributes:` block), RS005 (no double backticks), RS020 / RS021 (a summary or field comment that should be a docstring; warn), RS023 (no filler opening), RS034 (descriptive, not imperative, opening; warn), RS036 (backtick a code reference; warn), RS037 (no suffix glued to a code span; warn), RS039 (backtick a bare code token beside a backticked sibling, over docstrings and comment blocks; warn), the docstring half of RS030 (terminal punctuation; warn), RS047 (an `Args:`/`Returns:`/`Raises:`/`Yields:` entry description opens with a capital — RS030's opening-capital complement; warn), the docstring half of RS045 (temporal / diff-narrative marker; warn), the docstring half of RS049 (acronym casing in prose; warn, fix), the docstring half of RS050 (disfavored Google Cloud product name; warn, fix), RS053 (a bulleted list holding a multi-sentence item is sentence-cased throughout — both the docstring and the cross-language comment half; warn), the docstring half of RS054 (the spaced `--` sentence-dash standard; warn, fix), RS056 (a section header outside the recognized Google set, like `Warns:`; warn), RS057 (sections out of the canonical `Args:` → `Returns:`/`Yields:` → `Raises:` → `Example:` order; warn), RS058 (an alias header — `Arguments:`, `Return:`, `Yield:` — instead of the canonical spelling; warn, fix), and RS059 (a second section of one family in a docstring; warn)
  - `imperative_verbs` — RS034's verb list and conjugation, split out of `docstrings` to avoid a same-file definition-order conflict (the check needs its callee below it, the verb table needs its conjugator above it)
  - `doc_fill` — RS009 (fill prose to 79 columns) and RS035 (summary line over 79 columns; warn, no fix — a summary cannot be reflowed)
  - `doc_value` — RS018 (documentation-value signal; warn), RS031 / RS032 (per-argument or return detail that belongs in an `Args:` / `Returns:` section; warn), RS041 (raise detail that belongs in a `Raises:` section; warn), RS043 (an exception the body raises but a present `Raises:` section omits; warn)
  - `testing` — RS002 (test naming), RS003 (mock ban), RS013–RS016 (test-quality smells; warn), RS060 (a test restating one repo file's literals; warn)
  - `complexity` — RS012 (cognitive complexity; warn)
  - `annotations` — RS040 (a type annotation nesting subscripted generics past two levels; warn)
  - `idioms` — RS046 (a `for i in range(len(seq))` loop that indexes only `seq[i]`, where direct iteration reads better; warn)
  - `signatures` — RS027 (too many positional arguments; warn), a stand-in for ruff's preview-gated PLR0917 — delete it when PLR0917 graduates (PROC-2319)
  - `import_layering` — RS017 (config-driven banned-import-by-path)
  - `encapsulation` — RS048 (a first-party import that reaches another package's `_`-private internals instead of its public surface; warn), the enforcement dual of RS029 scoped to imports sharing the importer's top-level package
  - `error_handling` — RS052 (an `except` tuple reaching past the failure it was written for, into two or more structural builtins or one beside a declared exception the builtins do not define, unless the handler ends in a `raise`; warn), about the shape of a handler where RS028 in `naming` is about what it calls the exception
  - `layout` — RS019 (module element and class member order; warn)
  - `comments` — RS022 (comment-tag format), RS038 (a wrapped tag comment indents its continuation past the tag; warn), the comment half of RS030, the comment half of RS045 (temporal / diff-narrative marker; warn), the comment half of RS049 (acronym casing in prose; warn, fix), the comment half of RS050 (disfavored Google Cloud product name; warn, fix), the comment half of RS054 (sentence-dash standard; warn, fix), and RS055 (a banner, section-divider, or framed-title comment is deleted, the grouping expressed with structure; warn), all run over Python, TOML, YAML, and shell comments
  - `visibility` — RS029 (a name used only in-package should be private; warn), the one package rule, run over every first-party file at once rather than per file
  - `ports` — RS006 (a port module holds no implementation) · `duration` — RS007 (a duration is a `timedelta`, not a raw `*_SECONDS` number) · `logging_phi` — RS008 (no `exc_info` on a PHI-safe logger call) · `filenames` — RS033 (extension and casing of the on-disk name, `.py` exempt; warn) · `equality` — RS042 (`__eq__` and `__hash__` defined as a pair, or neither; a stand-in for ruff's preview-gated `PLW1641`)

  Support modules: `_violation` (the `Violation` record, `Severity` enum, and `RSnnn` id constants) · `_registry` (the `RULES` mapping of id to check functions, `PACKAGE_RULES`, `run_rule`, `ALL_RULE_IDS`) · `_catalog` (the agent-facing rule metadata — `RuleDoc` / `Example`, `RULE_DOCS`, `rule_doc`, `has_guidance` — the `explain` surface renders; every rule has a one-line `summary`, and the ones where general knowledge falls short add `rationale` / `examples` / `signals` / `reference`) · `__init__` (re-exports the whole public surface, so `from repostyle.rules import <name>` is stable).

  Adding a rule: write a `check_*` in the module it belongs to, add the id to `_violation`, register it in `_registry.RULES`, re-export from `__init__`, add a `RuleDoc` to `_catalog.RULE_DOCS`, and add a parametrized test.

- `src/repostyle/_shared.py`, `src/repostyle/_comments.py` — package-level shared infrastructure both the rule modules and the top-level `runner` / `suppressions` consume, so they sit above the `rules` package rather than one level down inside it, where a top-level importer would reach into its internals (RS048). `_shared` holds the cross-module helpers (`find_pyproject`, the `[tool.repostyle]` config-table and `.gitignore` readers, `_parse_python`); `_comments` the per-language `#`-comment extractor (`extract_comments`, `COMMENT_SUFFIXES`) RS009 / RS022 / RS030 and the suppression parser share — Python via the tokenizer, TOML, YAML, and shell via a string- and block-aware line scan.

- `src/repostyle/runner.py` — config resolution (`select` minus `ignore`, and the promotion set: every id, or the `error` list alone under `warnings-as-errors = false`), pyproject and baseline-path discovery, and linting a path with the enabled rule set.

- `src/repostyle/suppressions.py` — the `# style: ignore[RSnnn]` line and `# style: ignore-file` whole-file directives the runner applies to drop findings.

- `src/repostyle/changed_lines.py` — the git-diff line set the CLI's `--diff` mode intersects findings against, so a finding is reported only on lines the change touched, plus `resolve_diff_base`, which defaults the comparison to the merge-base of `HEAD` and the repo's default branch and returns `None` when none resolves so the CLI can refuse the run.

- `src/repostyle/baseline.py` — the `.repostyle-baseline.json` record of a tree's pre-existing findings, counted per file per rule so an edit that moves a finding does not resurrect it. `build` counts a scan, `refresh` merges a rescan while admitting only the backlog of rules the baseline predates, and `filter_baselined` drops a path's grandfathered findings. It is what lets every selected rule be an error without failing a repo on debt it did not just write.

- `src/repostyle/cli.py` — the `repostyle` console script the hook invokes; a directory argument recurses into its lintable files (pre-commit itself always passes individual files), its deprecated `--diff` flag scopes findings to git-changed lines, its `--warnings-as-errors` / `--no-warnings-as-errors` pair overrides the config's severity mode for one run, its `--write-baseline` / `--update-baseline` flags record or refresh the grandfathered backlog and `--no-baseline` ignores it, its `--fix` flag rewrites the mechanically-fixable findings in place (RS005 double-to-single backticks, RS009 reflow, RS030 terminal punctuation, RS049 acronym recasing, RS050 term rewrites, RS054 dash standardization, RS058 section-header canonicalization — the set in `_registry.FIXABLE_RULES`), and its `explain RSnnn`/`explain --all` subcommand prints a rule's card. A finding from a rule with a card prints a one-line `explain` pointer to stderr unless `--no-explain-hint` is passed, and a run that tolerated warnings closes with a stderr count of them, so an advisory backlog is never silent.

- `src/repostyle/explain.py` — renders a `RuleDoc` into the agent-facing explanation card (`explain_rule`) and the discovery hint, wrapping prose to 79 columns and leaving example code verbatim.

- `tests/` — `test_rules.py` (per-rule behavior), `test_runner.py` (config and dispatch), `test_cli.py` (CLI output and exit status), `test_suppressions.py` (suppression directives), `test_changed_lines.py` (the `--diff` line set and diff-base resolution), `test_baseline.py` (the grandfathering record), `test_complexity.py` (RS012), `test_annotations.py` (RS040), `test_idioms.py` (RS046), `test_import_layering.py` (RS017), `test_doc_value.py` (RS018, RS031, RS032, RS041, RS043), `test_layout.py` (RS019), `test_doc_form.py` (RS020, RS021, RS023, RS034), `test_doc_fill_reflow.py` (RS009 reflow, RS035), `test_visibility.py` (RS029), `test_comment_tags.py` (RS022), `test_signatures.py` (RS027), `test_filenames.py` (RS033), `test_encapsulation.py` (RS048), `test_cross_language.py` (the `extract_comments` `#`-comment extractor for TOML, YAML, and shell, plus the cross-language behaviour of RS009/RS030/RS045/RS053/RS054/RS055), `test_explain.py` (the `explain` cards, the catalog-completeness and abbreviation-map checks, and `has_guidance`), and `test_fix.py` (the RS005/RS030/RS049/RS050/RS054 fixers and the `--fix` composition in `runner.fix_path`), with a git repo from the `conftest.py` fixture.

- `ruff-base.toml`, `.pre-commit-hooks.yaml` — the shared ruff baseline and the hook definitions consumers reference. `.pre-commit-hooks.yaml` exports both the `repostyle` linter hook and the `repostyle-*` gate hooks (bandit, vulture, deptry, interrogate, codespell for Python; shellcheck and shfmt for shell scripts) that wrap the house third-party gates with their versions pinned here; mypy, pyright, and pip-audit stay consumer-side because they need the consuming repo's own environment.

## Style this repo holds itself to

These are the general house conventions — the subset that applies to this package's own code. Several are rules this package itself defines, so it holds itself to them too.

- Descriptive Google-style docstrings stating the unit's own contract in the third person (`Returns the lease.`, not `Return the lease.`; RS034 catches the common openings) — no caller postulation, no implementation mechanics, no narration of rejected alternatives. Comments only where the *why* is non-obvious.
- Line length 88; docstring and comment paragraphs fill to 79 columns (RS009), and a docstring summary line stays within 79 columns too, shortened by hand since it cannot be reflowed (RS035, warning).
- Single backticks in docstrings and prose, never double (RS005). A code name a docstring references — a parameter, import, class, accessed attribute, or the literals `None`/`True`/`False` — is wrapped in single backticks; RS036 flags the code-shaped ones mechanically (warning), leaving a lowercase name that doubles as English to review. A code span ends on a word boundary — no possessive, plural, or verb suffix glued onto the closing backtick, a hyphenated compound like `-typed` excepted (RS037, warning).
- Every docstring prose unit — the summary, a body paragraph, and an `Args:`/`Returns:`/`Raises:`/`Yields:` entry — ends with terminal punctuation (`.`, `!`, or `?`), per PEP 257 (RS030, warning). A Google-section entry description is treated as a full sentence, so it also opens with a capital letter — `bar: A bar.`, not `bar: a bar.` — RS030's opening-capital complement (RS047, warning). A docstring uses only the recognized Google sections — `Args:`, `Returns:`, `Yields:`, `Raises:`, `Note:`, `Example:` — never an invented or Sphinx-imported header like `Warns:` (RS056, warning), keeps them in the canonical `Args:` → `Returns:`/`Yields:` → `Raises:` → `Example:` order (RS057, warning), spells each canonically — `Args:`, not `Arguments:`; `Returns:`, not `Return:`; `Yields:`, not `Yield:` (RS058, warning, fixable) — and holds at most one section per family (RS059, warning). A bulleted list holding a multi-sentence item is sentence-cased throughout, while an all-fragment list may stay lowercase (RS053, warning). A comment, by contrast, takes no trailing period on a single-line fragment but punctuates multi-line or multi-sentence prose. A tag comment (`TODO(TICKET): ...`) that wraps indents its continuation past the tag, so the wrapped text reads as one unit; an unrelated note is set off by a blank line instead (RS038, warning).
- Docstring and comment prose sets a clause off with the house sentence dash, the spaced `--`, never an em dash, en dash, or bare spaced hyphen (RS054, warning, fixable); a numeric or `RSnnn` range keeps its unspaced en dash, and CLI flags, arithmetic, and backtick spans are never touched. A banner comment is deleted rather than styled, whether a bare divider or a framed title like `# --- main ---` (RS055, warning). The grouping it decorates belongs to structure: the file splits, gathers the section into a class, or opens the run with a sentence comment.
- Acronyms stay in their canonical casing in CapWords identifiers (RS001): `FHIRClient`, not `FhirClient`. The same acronym keeps that casing in docstring and comment prose beside the code (RS049, warning, fixable): `IPv6`, not `ipv6`; `NAT`, not `Nat`. A whole-word match only, so a substring or a hyphenated compound (`fhir-ingestor`) is left alone, and an acronym whose lowercase doubles as an English word (`SMART`, `ID`) is dropped from the prose rule. A disfavored Google Cloud product or brand name in the same prose is rewritten to its current form (RS050, warning, fixable): `Cloud Storage`, not `GCS`; `Google Cloud`, not `GCP`. `GCP` is dropped from RS049's prose set, since RS050 owns it there. See `docs/gcp-naming.md`.
- Spell names out; the banned abbreviations in RS010 (`cfg`, `ctx`, `req`, `resp`, `conn`, ...) are rejected. Name a class for its responsibility, not a vague `Manager`/`Helper`/`Util` role (RS011). Booleans read as a positive yes/no question: a `bool`-annotated name carries an `is`/`has`/`can`/`should` prefix (RS026) and never embeds `not` or `no` (RS024); both warn rather than fail. `make_` is for test fixtures only; a production `make_` is rejected (RS025). An `except ... as` alias is `exc` (`exc2` when nested) or a descriptive name, never `e`/`ex`/`err` (RS028). An `except` tuple catches the failure the block was written for, not two or more structural builtins at once, nor one beside a declared exception — stdlib, third-party, or the project's own — that already names the failure the block handles; a handler ending in a `raise` is a converting boundary and exempt (RS052, warning).
- Per-field attribute docstrings on dataclasses, not a Google `Attributes:` block (RS004). Module-level duration constants are `timedelta`, not raw `*_SECONDS` numbers (RS007).
- A non-Python filename prefers `.yaml` over `.yml` and kebab-case for a multi-word name, except `CLAUDE.md` (a fixed name Claude Code's tooling looks up exactly) and `README.md`/`CHANGELOG.md` (the older, more entrenched Unix/GNU and GitHub community-health-file convention of all-caps project metadata) (RS033, warning).
- No relative imports; strict type hints. A leading-underscore module or name is internal to the package that holds it, so other code reaches it only through the public surface that package re-exports from its `__init__`, never by importing its `_`-private members directly (RS048, warning).

Testing:

- Test functions follow `test_<StateUnderTest>_<ExpectedBehavior>` in PascalCase (RS002), one test class per public callable, ordered happy path then edge then error.
- Fakes, not mocks; assert observable outcomes, not call choreography; collapse cosmetic input variation into `@pytest.mark.parametrize` with `ids`.

## Commits and PRs

The repo squash-merges, so the PR title becomes the commit subject on `main`, and release-please reads that subject to compute the version bump. Title PRs as Conventional Commits with the Linear ticket (or `NO-ISSUE`) in the scope:

- `feat(PROC-123): add the no-bare-except rule` — a feature, bumps the minor.
- `fix(NO-ISSUE): correct the doc-fill boundary off-by-one` — a fix, bumps the patch.
- `feat(PROC-123)!: ...` or a `BREAKING CHANGE:` footer — bumps the major (the minor while the package is pre-1.0).
- `chore`, `docs`, `ci`, `refactor`, `test` produce a changelog entry but no release.

The scope carries the ticket so the title records it alongside the conventional-commit type. The subject after the type is lowercase. Commit subjects (within a branch) stay imperative and need no ticket — the title carries it.

## Release

release-please maintains a release PR off `main`; merging it cuts the `repostyle-vX.Y.Z` tag, the GitHub Release, and the `CHANGELOG.md` entry, then the workflow builds the wheel and publishes it to PyPI through trusted publishing, so no API token is stored in the repo. A `workflow_dispatch` run republishes the current `main` to either TestPyPI or PyPI. The version in `pyproject.toml` is release-please-managed; never edit it by hand. Consumers pin the `repostyle-v` tag in their pre-commit config, or `pip install repostyle` for non-hook use.

## Where to find context

- The judgment half of the house style — what a linter cannot decide — lives in `docs/judgment-conventions.md`; the Google Cloud naming convention behind RS050 and RS051 lives in `docs/gcp-naming.md`.
- Resolve the Linear ticket in the PR title before reading a diff; do not invent motivation when the ticket or MCP tools are unreachable.

## Agentic conventions

CI is the floor that blocks merge: ruff format and lint, pytest on the 3.11 floor and 3.13 ceiling, and the conventional-commit PR title check. Style beyond what those enforce is upheld by review. Never amend or force-push a shared branch.
